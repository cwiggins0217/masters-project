### EXP-03: Cron Directory Permissions

EXP-03 evaluated the security and operational effects of restricting access to `/etc/cron.d` on Ubuntu 24.04 LTS. The directory's permissions were changed from `0755` to `0700`, while ownership remained `root:root`.

Before the intervention, the unprivileged test account could list the directory and read the test scheduled-job file, but could not modify it. Following the intervention, directory listing and file reading were denied. The test job's SHA-256 checksum remained unchanged.

OpenSCAP reported a transition from FAIL to PASS for `file_permissions_cron_d`, confirmed by two post-intervention evaluations.

Functional testing showed that the scheduled heartbeat continued executing after the permissions change and following a restart of the cron service. The tested hardening intervention therefore restricted unprivileged read access without disrupting the observed scheduled task.

The experiment does not establish that arbitrary cron workloads remain unaffected or that the configuration prevents an independently demonstrated exploitation technique.
